# liskill-members

liskill 会员技能仓库。通过对话，从真实素材出发，完成内容定位、素材挖掘、选题分析及特定类型的写作与审稿。

适用于支持 Agent Skills 和本地文件读取的工具。不同客户端的安装入口、命令展示和脚本执行能力不同；不能执行脚本的客户端需要在终端完成更新，再按其导入方式重新加载。

---

## 🔧 安装后排查指南（如果技能列表看不到）

> **请 Agent 重点读这一段：** 如果用户说"技能在对话里能用，但可视化技能列表看不到"，按下面步骤排查。

**第一步：检查所有可能的安装目录**

逐个查看下面这些目录里有没有 `li` 和所有 `li-` 开头的技能目录：

| 目录 | 适用客户端 |
|---|---|
| `~/.agents/skills/` | 通用 Agent、npx 全局安装 |
| `~/.claude/skills/` | Claude Code |
| `.doubao/agent_mode/workspace/.skills/` | 豆包电脑版（内置技能目录） |
| `.doubao/agent_mode/workspace/.user_skills/` | 豆包电脑版（用户技能目录） |

**第二步：检查符号链接是否有效**

逐个检查每个 `li-*` 目录是不是符号链接：
- 如果是符号链接，用 `readlink` 看链接指向的目标路径是否存在
- 如果目标不存在（悬空链接），或者目录缺失，重新执行安装命令修复：
  ```bash
  npx -y skills add https://gitee.com/LTX12/liskill-members.git -g --all
  ```

**第三步：确认文件完整**

重装后再次确认：
- 所有 `li-*` 目录都在
- 每个目录里有完整的 `SKILL.md`（文件非空、能读取，文件头有 `name` 字段）

**第四步：清理旧版残留**

如果重装后可视化列表还是看不到，检查有没有旧的大写残留目录（`Li`、`Li-Eight-Audits` 等），有就删掉。

**完成后告诉用户：** 目录是否存在、链接是否有效、SKILL.md 是否完整、可视化列表是否恢复正常。

## 安装或更新

推荐使用一行命令安装到全局（需要 Node，npx 会自动下载）：

```bash
# Gitee（国内用户）
npx -y skills add https://gitee.com/LTX12/liskill-members.git -g --all

# GitHub（国外用户）
npx -y skills add Li-TongXue/liskill-members -g --all
```

安装完成后，直接在 Agent 中说需求（例如「帮我从今天的工作里找能拍的事」），或使用 `li` 主入口 / 各技能的英文机器名即可。

> **豆包电脑版用户请注意**：豆包技能列表只自动识别豆包工作区下的用户技能目录 `.user_skills`（以及内置技能目录 `.skills`），不会识别 `~/.agents/skills` 或 `~/Doubao/skills`。仅运行上面 `-g` 全局命令后，豆包技能列表可能仍显示旧版或不显示。豆包内的正确做法：
> 1. 直接发送安装指令，让 Agent 把技能安装到本机豆包工作区的 `.user_skills` 目录；
> 2. 或在终端运行上述命令后，把 `skills/` 下的技能目录复制到 `.user_skills`；
> 3. 装完或更新后**新建对话**，豆包技能列表即显示最新版本。

**更新**：重新运行上面的命令即可更新到最新版本。

> 旧版安装过中文 / 大写名称目录（`Li-*`）的用户，更新后如果发现旧名字的技能还在，把它从技能目录中删除即可（例如删除 `~/.agents/skills/` 下 `Li-` 开头的旧目录），保留 `li-` 开头的新版本。

### 可选：使用 li-update 自动迁移（需要 Git + Python 3.10+）

如果已经安装过旧版本、或希望自动清理旧目录并保留本地修改，可以使用仓库内置的更新器（可选，普通用户不需要）：

```bash
git clone --depth 1 https://gitee.com/LTX12/liskill-members.git liskill-members-update
python3 liskill-members-update/skills/li-update/scripts/update.py --apply
```

Windows 安装 Python 后可将 `python3` 换成 `py -3`。更新器只维护官方 liskill 集合：识别旧目录并迁移、备份后替换、失败回滚、检测本地修改时停止并保留原状。详见 [安装与迁移](docs/installation.md)。

## 开始使用

直接说需求即可，例如“帮我从今天的工作里找能拍的事”“检查这段口播稿有没有画面感”。不确定时使用 `li` 主入口。

### 一步一技能：带着做完一条作品

`li` 主入口把一条短视频拆成 12 步，先问你走到了哪一步（没素材 / 有素材 / 有选题 / 有稿子），再从那一步进入：

| 步 | 步骤 | 对应技能 |
|---|---|---|
| 1 | 账号定位 | `li-account-positioning`（从零定位）；已经发了一批内容时用 `li-agenda-setting` 检查印象 |
| 2 | 素材 | `li-material-mining` |
| 3 | 选题角度 | 发散：`li-angle-team`；收敛：`li-conflict-topics` / `li-stasis-topoi` / `li-public-issues` / `li-topic-ladder` |
| 4 | 值不值得拍 | `li-worth-shooting` |
| 5 | 转发 | `li-social-currency` |
| 6 | 脚本形式 | `li-script-form`（城市印象、故事 Vlog 分别转 `li-city-impressions`、`li-story-vlog`） |
| 7 | 开头 | `li-script-opening` |
| 8 | 完整脚本 | `li-script-writing` |
| 9 | 八步审核 | `li-eight-audits` |
| 10 | 修改 | `li-eight-audits` 重点改造（Vlog 文风用 `li-story-vlog` 改稿模式） |
| 11 | 再审 | `li-eight-audits` |
| 12 | 标题封面拍摄剪辑 | `li-publish-pack`；拍摄剪辑建设中 |

- **内容卡**：每条作品在当前工作目录生成一张 `内容卡_<主题>.md`，栏目为素材、选题与角度、受众、值不值得拍、转发判断、形式、开头、脚本、审核记录、发布。每个技能读卡、只更新自己的栏目，下一步不用重新交代材料。不能写文件的客户端（如豆包）会在回复末尾给出「交接卡」，复制后在下一步粘贴回来即可。
- **下一步**：每一步结束时给出「✅ 第 X 步完成 / 👉 下一步是第 Y 步，回复「继续」开始 / 也可以回到或跳到某一步」。
- **带练模式**：遇到要你判断的地方（选哪条素材、哪个选题、哪版改法）一定停下来等你选，选完才往下走，不会替你一口气跑完。技能 299 就能装上，判断得自己练。

机器名称使用小写英文和连字符，目录与 `name` 一致。Codex 可以用 `$li-material-mining`；提供斜杠技能菜单的客户端应以菜单实际展示的命令为准。中文名称用于显示与自然语言表达，不另外承诺注册中文斜杠命令。

| 当前情况 | 可以这样说 |
|---|---|
| 想被带着从头做一条 | 用 li，带我从第一步做一条视频 |
| 刚开号，不知道账号往哪个方向做 | 用 li-account-positioning，带我从零做账号定位 |
| 不知道拍什么 | 用 li-material-mining，问问我今天发生了什么 |
| 有素材，不知道往哪个方向讲 | 用 li-angle-team，从 13 个视角找出这件事还和谁有关 |
| 有话题但太平 | 用 li-conflict-topics，看看这个话题有没有真实冲突 |
| 题目太小众，只有同行会看 | 用 li-topic-ladder，看看这个素材能推到哪一层、还和谁有关 |
| 有了选题，拿不准值不值得拍 | 用 li-worth-shooting，看看这个题能不能带来客户 |
| 想知道观众为什么转发 | 用 li-social-currency，判断这个题的分享性 |
| 选好题了，想把稿子写出来 | 用 li-script-form，从结构库里挑一个结构，再一路写到全稿 |
| 有一段真实经历想写旁白 | 用 li-story-vlog，把这些材料写成克制的 Vlog |
| 已有稿件要检查表达 | 用 li-eight-audits，检查这段稿子的画面和细节 |

## 技能清单

清单由 `skills.json` 生成，区分业务能力、路由入口与更新工具。Level 1 需要共同补充材料，不保证完整成稿；Level 2 已有内置方法或问答流程，仍须使用真实输入。具体理由见各 Skill 的 `metadata.completion_reason`。

<!-- skills:start -->
按短视频制作流程排序：定位 → 素材 → 选题 → 选题判断 → 文案脚本 → 审核 → 发布。

| # | 阶段 | 调用名 | 中文名称 | 用途 |
|--|------|--------|----------|------|
| 1 | 入口 | `li` | Li 主入口 | liskill 主入口：按「一步一技能」的 12 步短视频流程，先问用户走到了哪一步（没素材 / 有素材 / 有选题 / 有稿子），再进入对应技能，并用内容卡把各步结果串成一条完整作品。用户明确调用 li、不知道该用哪个 Li 技能、想被带着从头做完一条作品，或一个任务需要多项 Li 能力配合时使用；已明确匹配单个业务技能时直接使用该技能。 |
| 2 | 定位 | `li-account-positioning` | 账号定位 | 按李同学的方法带实体老板从零定抖音账号——先看同城对手，再算清变现链路（流量、需求、信任，客单价与成交路径），找一个有人要、没人占、自己占得住的空位，从真实经历提炼人设，用身份、场景、地域、金额等元素筛人，落成一句话定位、账号议程、账号门面和前 60 条的验证节点。开新号、不知道拍什么方向时使用；已发一批想查印象跑偏时不使用。 |
| 3 | 素材 | `li-material-mining` | 素材挖掘 | 通过逐轮追问，从用户的工作和日常经历中挖掘真实的短视频素材，并形成可拍的选题。用户不知道拍什么、觉得日常没有内容，或希望通过聊天寻找素材时使用；已有明确素材、只需要改稿时不使用。 |
| 4 | 选题 | `li-angle-team` | 多视角找角度 | 用 13 个视角（含李老师的元素召人）分别找一份素材还能和哪些人、在什么处境下发生真实关系，每条连接标明召来的是不是客户、能否连回生意，分批摆出完整连接地图，由用户自己挑。有素材不知往哪讲、想知道「这件事还和谁有关」时使用；不排序、不推荐，不写标题和全稿。 |
| 5 | 选题 | `li-conflict-topics` | 冲突性选题 | 判断普通话题是否适合以冲突展开，找出主冲突并形成不同力度的选题。用户觉得话题太平、想找张力或把话题推进成题时使用；不强推没有真实分歧的教程和通知。 |
| 6 | 选题 | `li-stasis-topoi` | 修辞学选题法 | 从已有事实和不同解释中识别核心争点，再选择因果、定义、对比等切口形成选题。用户想弄清在争什么或选择争议内容角度时使用；事实尚不清楚时先补材料。 |
| 7 | 选题 | `li-public-issues` | 公共问题升维 | 检验具体事件或个人观察是否具有公共性，用事实和机制假设形成值得讨论的公共问题。用户觉得现象不对劲、想讲清背后机制或让更多人理解其影响时使用；证据不足时不强行扩大结论。 |
| 8 | 选题 | `li-topic-ladder` | 话题扩圈阶梯 | 按李同学的需求理论，把只拍产品的小题，从产品本身一层层推到客户要办的事、更大的场景人群和普遍关心的事，每层写清多了谁、召来的是不是客户、怎么连回生意，过程主线始终回到老板的业务。用户觉得题太小、只有同行或熟客会看、想让更多人关心时使用；连不回生意的层级不用，不承诺播放量。 |
| 9 | 选题判断 | `li-worth-shooting` | 值不值得拍 | 按李同学「需求决定一切」，结合账号定位给已选好的选题下结论——拍、换个角度拍或不拍。依次看需求档位、选题元素召来的人、能否回到生意和信任、能拍成作品还是只是记录、能否做成系列和风险，给出改法、建议脚本类型和改判条件。用户有了选题想知道值不值得拍时使用；不预测播放量，不判断转发性，不负责把题推大。 |
| 10 | 选题判断 | `li-social-currency` | 社交货币选题判断 | 从观众愿意转给谁、转发如何影响自身形象出发，判断和改造选题的分享性。用户明确关心转发、分享或社交货币时使用；不将转发性等同于整体拍摄价值、获客价值或播放量预测。 |
| 11 | 内容定位 | `li-agenda-setting` | 议程设置内容定位 | 分析一组内容会让观众形成什么稳定印象，并给出内容支柱和最小修正建议。用户检查账号长期印象或希望反推内容定位时使用；不用于单条稿件的表达润色。 |
| 12 | 文案脚本 | `li-script-form` | 脚本形式 | 按李同学的干货、过程、故事、情绪四类脚本，判断一条已选定选题该满足观众哪种需要，定主类型和辅助类型，再从结构库对应分组推荐 2–3 个结构，由用户选定后对照素材缺口和该类写作要求的缺口。用户有了选题、问「这个题怎么拍」「用哪个结构」时使用；没有选题先回选题步骤，已有成稿时不使用。 |
| 13 | 文案脚本 | `li-script-opening` | 开头 | 按李同学「开头要让目标用户觉得和我有关」的方法，结合选定结构的开头规则和脚本类型，用真实素材分别以说什么、什么场景、什么问题三种筛选方式写 3 个开头，标明吸引谁和关联线索，由用户选定。已选好结构、要写开头或问「前几秒怎么留人」时使用；还没选结构先回脚本形式；只要发布标题或封面文字时不使用。 |
| 14 | 文案脚本 | `li-script-writing` | 完整脚本 | 按已选定的结构和开头，用用户确认过的素材写出完整口播稿；写时逐项满足干货、过程、故事、情绪四类脚本各自的写作要求，写完做一轮精修（元素叠加、真实感、评论缺口、信息密度与推进、回到业务），缺素材处写待补占位，不代编。用户已选好结构和开头、要写全稿时使用；还没选结构先回第 6 步；已有成稿只需审核时不使用。 |
| 15 | 文案脚本 | `li-city-impressions` | 城市印象文案生成 | 从用户对城市的真实观察中，组织误解与事实反转的短视频口播脚本。用户希望讲述城市印象或本地生活体验时使用；缺少真实反转经历时先补素材，不虚构故事。 |
| 16 | 文案脚本 | `li-story-vlog` | 故事事件「Vlog」写作 | 将真实经历或人物关系写成克制、留白的 Vlog 旁白，也可按此文风修改已有稿件。用户要求故事 Vlog、事件旁白或克制叙事时使用；不用于强观点口播、教程或强转化带货。 |
| 17 | 审核 | `li-eight-audits` | 八大审核法 | 对已有中文口播稿或短视频脚本按「八步审核流程」逐条诊断：选题=需求+解决方案、开头5秒勾引、陌生化+普遍性、信息清单、明确的朋友和敌人、植入个人营销点、信息效率、筹码，判断能不能发、卡在哪几步、最致命的缺口，并给出可直接使用的改写示范。用户要求审稿、改文案、判断文案能不能发、增强画面感或流量时使用；不用于从零写作、标题起名、发布合规判断或整体流量归因。 |
| 18 | 发布 | `li-publish-pack` | 发布文案标题封面 | 根据用户提供的逐字稿、选题或素材，为抖音、视频号和小红书生成平台适配的发布标题、发布文案与封面文案。用户写好内容要发布、需要跨平台适配、或问标题/文案/封面怎么写时使用；只写口播脚本或纯审稿时不使用。 |
| 19 | 工具 | `li-update` | 更新 liskill | 检查或更新官方 liskill-members 的安装。用户要求更新、升级或检查 Li 安装状态时使用；仅询问版本或更新方式时先解释，只有明确要求更新才执行写入。 |

## 后续更新

**怎么更新？** 直接对我说"更新 liskill"就行。更新完新开一个对话，就能看到最新版了。

**只想检查有没有新版本？** 对我说"检查 Li 是否需要更新"，我只会告诉你有没有新版本，不会真的更新。

## 常见问题

### 可视化技能列表里看不到？

把下面这段话发给 Agent，让它帮你排查修复：

> 我电脑上安装的 liskill 技能（来源 https://gitee.com/LTX12/liskill-members.git ）在 Agent 里能识别，但可视化技能列表里看不到。请帮我排查并修复：
> 1. 先查看技能安装目录里有没有这些技能：`~/.claude/skills` 和 `~/.agents/skills` 两个目录下，检查 li、li-account-positioning、li-material-mining、li-angle-team、li-conflict-topics、li-stasis-topoi、li-public-issues、li-topic-ladder、li-worth-shooting、li-social-currency、li-agenda-setting、li-script-form、li-script-opening、li-script-writing、li-city-impressions、li-story-vlog、li-eight-audits、li-publish-pack、li-update 这 19 个小写目录是否存在
> 2. 逐个检查这些目录是不是符号链接：如果是，用 `readlink` 看链接指向的目标路径是否存在；如果目标不存在（悬空链接）或者目录缺失，重新执行安装命令修复：`npx -y skills add https://gitee.com/LTX12/liskill-members.git -g --all`
> 3. 重装后再次确认 19 个小写目录都在，且每个目录里有完整的 SKILL.md（文件非空、能读取，文件头有 name 字段）
> 4. 如果重装后可视化列表还是看不到，检查有没有旧的大写残留目录（Li、Li-Eight-Audits 等），有就删掉
> 5. 完成后告诉我：目录是否存在、链接是否有效、SKILL.md 是否完整、可视化列表是否恢复正常

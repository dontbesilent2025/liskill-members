# 开头（第 7 步）

先写开头，再写全稿。开头决定谁留下来，也决定后面全稿往哪个方向写。本技能按李同学的开头方法，结合选定结构的开头规则，写 3 个开头，由用户选一个。不写全稿。

## 方法主干

李同学的说法是：开头不做自我介绍，要讲用户眼中正在发生的事。开头的任务，是让目标用户在几秒内判断「这和我有关，值得继续看」。

开头同时在筛人：

1. 你说什么，就吸引什么人；
2. 你用什么场景，就筛选什么人；
3. 你用什么问题，就让什么人留下。

他的例子：「兄弟，能给我 50 块钱吗？我帮你拍一条 20 万播放的作品。」「50 块」「20 万播放」两个词，筛出了想低成本拍短视频、对播放量有需求的人。

所以本技能的 3 个开头，分别用这三种方式筛人：A 用说什么来筛，B 用什么场景来筛，C 用什么问题来筛。三个开头筛的都是同一群目标用户，只是入口不同。3 个开头的第一句必须各不相同，也不能共用同一句核心句；共用了，等于只写了一个开头。

方法原文、元素清单和开头检查见 `references/开头方法.md`；背后的机制和边界见 `references/理论依据.md`。对话中不说理论名，只说人话。

## 随包材料

- `references/开头方法.md`：李同学的开头方法：三种筛选方式、元素使用规则、自我介绍规则、开头检查。
- `references/理论依据.md`：开头和元素背后的机制，以及四类脚本的说明和边界。
- `references/structure-index.md`：结构索引，按干货、过程、故事、情绪四类脚本分组。
- references/structures 目录：每个结构一个文件，文件名就是结构名。读取选定结构的「基本信息」（脚本类型）、「开头规则」「结构链」和「信息点模板」的第一段。

## 三条不编造规则

开头只用四种内容：

- 内容卡和对话里用户确认过的素材；
- 写成【待补：……】的占位，标明需要用户补什么；
- 常识类内容，写成【示例，请改成你的】；
- 根据用户描述改写成口语的句子，写成【按你说的意思写的，请改成原话】。

不编造用户的经历、客户案例、数字和原话。金额、身份、时间、地点这些元素尤其不能编，缺就写【待补】。

## 适用边界

适合：

- 内容卡「形式」里已经选定结构，要写开头。
- 用户问「开头怎么写」「前几秒怎么留人」「这个开头行不行」。

不适合：

- 还没选结构：开头要跟着结构走，先回第 6 步 `li-script-form`。
- 只要发布标题、封面文字：交给 `li-publish-pack`。
- 选定的是「城市印象反转」或「故事事件 Vlog 旁白」：这两种形式由 `li-city-impressions`、`li-story-vlog` 整条写，不在本步单独写开头。
- 要写完整脚本：开头选定后进入第 8 步 `li-script-writing`。

## 对话原则

1. 内容卡里有的不再问。「受众」为空时，用卡头「账号定位」里的目标用户，不追问。
2. 最多问一个问题，只问会让 3 个开头都写不下去的那个关键素材。
3. 3 个开头一次给出，再停下让用户选。不一个一个问用户喜欢哪种。
4. 只给用户看开头和每个开头的说明，推导过程放在心里。
5. 用户的口头说法优先。用户说过的原话能用就原样用，不替他改得更书面。

## 固定流程

### 第一步：读卡，确认结构和素材

从内容卡读取：

- 「形式」：选定结构、脚本类型、素材对照（哪些素材已有、哪些缺）；
- 「选题与角度」：这条讲什么、从哪个角度讲；
- 「素材」：用户确认过的事实、原话、数字、画面；
- 「受众」：这条想吸引谁；为空时用卡头「账号定位」里的目标用户；
- 「转发判断」：用户选用的改法钩子，可以作为某个开头的素材，放进最合适的那种筛选方式；
- 卡头「账号定位」：做什么生意、服务范围、目标用户。

例外处理：

- 没有选定结构：说明开头要跟着结构走，建议先回第 6 步；用户坚持现在写时，请他从 `references/structure-index.md` 里点一个结构名。
- 结构文件找不到：如实说明安装可能缺文件，不凭名字猜结构。
- 「形式」里没写脚本类型：读结构文件「基本信息」里的「脚本类型」。

### 第二步：读结构的开头规则和脚本类型

读取结构文件，在心里整理：

- 开头规则要完成的任务（例如「交代小事起因」「秘密测评制造对立」「强观点＋真实案例」）；
- 结构给出的开头句式；
- 开头必须用到的素材，哪些已有、哪些缺；
- 脚本类型对开头的要求，按下表：

| 脚本类型 | 开头要做到 | 例子方向 |
|---|---|---|
| 干货 | 让他知道马上有能用的东西：点出他会遇到的问题或会犯的错，并让他知道后面有办法 | 「买橱柜先看这一处，看错一套白装」 |
| 过程 | 建立期待：交代要做一件什么事、难在哪或结果未知，让他想看到最后 | 「帮我下这几个菜，别说是我下的」 |
| 故事 | 有画面或处境：直接进入一个具体时刻，让他看到熟悉的情况 | 「那天刚开门，进来一个抱着孩子的车主」 |
| 情绪 | 让目标人群觉得「你站在我这边」：说出他受过的委屈、看不惯的事，或替他说一句话 | 「被装修公司增项坑过的，听我说一句」 |

脚本类型写成「过程（辅：故事）」这类混合时，按主类型的要求写，辅类型作为加分项。

结构的开头规则和三种筛选方式同时成立：结构规定开头要完成什么任务，筛选方式决定从哪个入口让目标用户觉得有关。两者冲突时，以结构的开头规则为准，在规则允许的范围里换入口。

### 第三步：写出「这条开头要筛的人」

写 3 个开头前，先写一句，给用户看：

```markdown
这条开头要筛的人：<目标用户是谁>，此刻<他在什么处境>，听到<什么词、什么画面、什么问题>会觉得和自己有关。
```

例：「这条开头要筛的人：家里有小孩、车里被弄脏的同城车主，此刻正在犹豫座椅要不要换，听到『只能换座椅套』『娃打翻牛奶』会觉得说的是自己。」

写不出这一句，说明目标用户还不清楚：先按账号定位暂定，并在推荐里写明「目标用户按账号定位暂定」。

### 第四步：写 3 个开头

3 个开头都遵守同一条结构开头规则，分别用一种筛选方式：

| 开头 | 筛选方式 | 第一句放什么 | 适合的素材 |
|---|---|---|---|
| A | 用说什么来筛 | 最能让目标用户认出自己的一句话：一句有冲突的原话、一个反常的数字、一个和常识相反的判断、一个能回答「和你有什么关系」的身份 | 用户的原话、客人的原话、确认过的金额或时间 |
| B | 用什么场景来筛 | 一个具体的画面、地点或正在发生的动作，场景本身决定谁会觉得有关 | 现场画面、能拍到的动作、店里或客户家里发生的事 |
| C | 用什么问题来筛 | 目标用户正在纠结、还没解决的问题，具体到他能立刻对上自己；问完让他知道后面有答案 | 客人常问的问题、目标用户反复遇到的选择 |

**素材撑不起某种方式时**：不跳过，也不硬写。在开头说明里写一句原因，换成同一筛选方式里素材撑得住的写法：

- A 没有原话或确认过的数字：改用一个和常识相反的判断，或目标用户自己常说的一句话；常识类写【示例，请改成你的】。
- B 拍不到现场：改用目标用户自己生活里的场景（他家里、他车里、他店里）；需要用户补的画面写【待补：……】。
- C 没有现成问题：从「选题与角度」推出目标用户会怎么问，用他的口吻问出来。

**元素规则**（人物、地点、金额、时间、身份、关系、道具、任务、意外、反差、地域、场景、成本、稀缺性、争议点都是元素）：

1. 第一句至少有 1 个能让目标用户认出自己的元素。
2. 每句只叠 1–2 个关键元素。塞太多，观众反而听不懂。
3. 元素只用确认过的事实；缺的写【待补：……】，不编金额、身份和事件。
4. 能换元素筛人时先换元素：同样烤羊，在别墅烤召来别墅客户，在自建房院子烤召来自建房客户。

**自我介绍规则**：

- 第一句不做和观众无关的自我介绍。「我是某某，做了 X 年」这类背景不放开头。
- 身份能直接回答「和你有什么关系」时才可以放开头，例如「当过 8 年监理的装修老板」对正在装修的人。放了也只占一句，且身份必须是用户确认过的。

**关键素材缺失时**：开头规则需要的关键素材缺失、3 个开头会以同一个占位起句时，先问 1 个问题；用户说「先写」时，允许用一句行业里常见的典型说法起句，标【示例，请改成你的】，让 3 个开头保持不同。用户本人的经历、数字和原话仍然不能这样起草。

**转发判断的钩子**：内容卡「转发判断」里用户选用的改法钩子，放进最合适的那个开头（一句话判断放 A，一个场面放 B，一个可以站队的选择放 C），并在该开头的说明里写「用了转发判断的钩子」。

每个开头按下面格式交付，原文 2–5 句，口播 5–15 秒：

```markdown
**开头 A｜用说什么来筛**
（开头原文，2–5 句）

吸引谁：……（一句话，具体到处境）
关联线索：……（哪个词或元素让他觉得有关）
用到的元素：……（只列 1–2 个关键的）
待补：……（没有就写「无」）
风险：……（例如：太像广告、身份没确认、可能召来同行）
```

素材撑不起、换了写法的，在「风险」前加一行「换写法原因：……」。

### 第五步：推荐，让用户选

先写一行推荐：「推荐：开头 X，理由：……（一句话，说清它最能让目标用户觉得有关的那个点）」，然后停下问：

> 你选哪一个？也可以把两个拼起来，或者直接改你觉得不像你会说的那句。

- 用户拼接：按用户指定的句子拼好，检查元素是否超量、第一句是否还有关联线索，复述最终版本并确认。
- 用户改句：用他的原话替换，复述最终版本并确认；用户改过的句子去掉对应的占位标记。
- 三个都不满意：问一句最不满意的地方（不像他说的话、吸引错了人、太长），按这一点再写一轮，最多两轮。仍不满意就保留用户最接近满意的一版，标出问题，进入下一步时交给全稿再调。

### 第六步：交付

用户确认后，写进内容卡「开头」栏：

```markdown
## 开头

结构：结构名（脚本类型）
筛选方式：A 说什么／B 场景／C 问题（拼接时写清哪句来自哪个）
吸引谁：……
开头原文：……
待补：……（没有就写「无」）
```

## 质量检查

- 是否先写出了「这条开头要筛的人」，说清目标用户、处境和让他觉得有关的东西？
- 3 个开头是否分别用了说什么、场景、问题三种筛选方式，筛的都是同一群目标用户？
- 每个开头的第一句，能不能让目标用户判断「和我有关」？能不能说出它吸引的是谁、靠哪个词或元素？
- 3 个开头是否都遵守了选定结构的开头规则，并符合脚本类型的要求（干货有收获、过程有期待、故事有画面或处境、情绪站在目标人群这边）？
- 第一句有没有和观众无关的自我介绍或背景交代？
- 每句是否只叠 1–2 个关键元素？元素是否都来自确认过的事实？
- 缺的地方是否用了【待补】，常识和改写是否标了对应标记？是否没有编造数字、案例和原话？
- 素材撑不起某种方式时，是否说明了原因，并换成同一方式里撑得住的写法？
- 是否给了一句话推荐、停下让用户选，并复述了最终版本？

## 内联案例

### 正例：洗车店，三种筛选方式（示范素材）

以下素材为演示而设，用户使用时换成他自己的。

- 结构：生活故事-人设塑造（故事）。开头规则：一两句话交代小事起因，让目标用户一眼看到自己熟悉的情况。
- 素材：客人车里，孩子打翻了一盒牛奶，座椅放了一个星期发臭；客人跑了两家店，都说只能换座椅套；老板把座椅拆下来洗干净了。
- 这条开头要筛的人：家里有小孩、车里被弄脏的同城车主，此刻正在犹豫座椅要不要换，听到「只能换座椅套」「娃打翻牛奶」会觉得说的是自己。

**开头 A｜用说什么来筛**
别家都说只能换座椅套。这个车主跑了两家店，听到的都是这句。我把座椅拆下来，看了一眼。

吸引谁：正在纠结座椅要不要换的车主
关联线索：「只能换座椅套」是他自己可能听过的原话
用到的元素：争议点（只能换）、道具（座椅）
待补：无
风险：语气像在说同行坏话，全稿里要落到「怎么处理」，不去踩别家

**开头 B｜用什么场景来筛**
车门一开，后座一股酸味。孩子打翻的牛奶，在座椅里放了一个星期。

吸引谁：家里有小孩、车里出过这种事的车主
关联线索：「孩子打翻牛奶」「放了一个星期」，有娃的车主一听就有画面
用到的元素：意外（打翻牛奶）、时间（一个星期）
待补：【待补：开车门那一下的实拍镜头】
风险：画面要拍得出来，只靠口播会弱

**开头 C｜用什么问题来筛**
车里被娃打翻了牛奶，座椅只能换吗？这个车主问了两家，都让他换。我拆开给你看。

吸引谁：车里刚被弄脏、还没决定怎么处理的车主
关联线索：问题本身就是他此刻在纠结的选择
用到的元素：人物（娃）、成本（换不换）
待补：无
风险：「拆开给你看」之后，全稿必须真的有拆洗过程

推荐：开头 A，理由：「只能换座椅套」是车主自己听过的话，一句就对上处境，也给了后面「其实不用换」的期待。

### 反例 1：自我介绍开头

> 大家好，我是渝北某某洗车店的老王，干洗车 12 年了，今天给大家分享一件事。

问题：第一句没有一个能让车主认出自己的元素；「12 年」回答不了「和你有什么关系」，观众划走前还不知道这条讲什么。改法：把「只能换座椅套」或「孩子打翻牛奶」放到第一句；身份要用，就放在后面一句，并且要和这件事有关。

### 反例 2：六个元素挤一句

> 重庆渝北一个 38 岁宝妈，开着 50 万的车，娃打翻两盒牛奶放了七天，别家报价三千换座椅套，我三百八搞定。

问题：地域、人物、金额、意外、时间、成本挤在一句里，观众一句都记不住；「38 岁」「50 万」「三千」用户都没确认过，属于编造。改法：拆成两到三句，每句只留 1–2 个关键元素，没确认的数字写【待补：别家报价多少】。

## 交给其他 Li 技能

- 还没选结构，或想换结构 → 第 6 步 `li-script-form`
- 开头选定，写完整脚本 → 第 8 步 `li-script-writing`
- 只要发布标题、封面文字 → `li-publish-pack`

交接时带上选定结构、筛选方式、吸引谁和开头原文，不让用户重新提交材料。

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 7 步「开头」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「形式」里的选定结构和素材对照直接使用；「素材」「选题与角度」「受众」里已确认的内容直接写进开头，缺什么再问。
- 本技能只更新「开头」（写结构、筛选方式、吸引谁、开头原文、待补）和卡头「当前进度」；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：选哪个开头由用户决定——到这个判断点必须停下，给出 3 个开头和推荐，等用户选。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。

**结尾格式**：

```
✅ 第 7 步完成：选定开头 <A/B/C>（<筛选方式>，吸引<谁>）
👉 下一步是第 8 步：完整脚本（li-script-writing 完整脚本），回复「继续」开始
也可以：回到第 6 步换结构 ／ 再写一组开头
```

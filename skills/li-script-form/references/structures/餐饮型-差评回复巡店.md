# 餐饮型-差评回复巡店

## 基本信息

- 脚本类型：过程
- 难度：3 级
- 一句话适合：收到差评的餐饮门店，用「老板暗中测评自家差评菜品」的视角，既回应差评，又展示品控重视和服务态度。
- 必需素材：3–6 道实际差评菜品、秘密下单的设定、属实的那一道差评、其余菜品的真实测评结果和小问题、处理方案
- 呈现形式：跟拍
- 篇幅：未标注
- 来源：cq-餐饮型-差评回复巡店；参考视频：抖音【蜡笔小锋】「差！差！差！没有一个差评是白吃的！必须整治」

## 什么时候选

- 餐饮门店收到了差评，想用视频既响应差评、又展示品控能力。
- 能真实拍摄测评过程，愿意「先骂自家」建立信任。
- 需要设计好「先骂一道、再轻放其余」的高举轻放节奏；拍不了真实测评时不要选。
- 差评里不是菜品本身的问题（如配送慢），不单独测评，放进最后的处理信息里说。

## 结构链

钩子开头（秘密下单）→ 展示菜品＋吐槽引共鸣 → 测评 1（先认差评＋埋冲突）→ 测评 2–N（照顾客情绪＋高举轻放＋处理方案）→ 情节冲突高潮 → 处理结果＋服务态度升华

## 需要的素材

| 素材 | 数量 | 来源 | 缺了怎么办 |
|---|---|---|---|
| 实际收到差评的菜品名称 | 3–6 道 | 用户亲历 | 追问 |
| 吐槽引共鸣的一句话 | 1 句 | 常识 | 可起草 |
| 秘密下单的设定（让谁帮忙下单、不让厨房知道） | 1 个 | 用户亲历 | 追问 |
| 属实的那一道差评：测评结果 | 1 道 | 用户亲历 | 追问 |
| 其余菜品的真实情况、小问题和处理方案 | 2–5 道 | 用户亲历 | 追问 |
| 情节冲突设计（如让厨师自己品尝争议菜品） | 1 个 | 用户亲历 | 占位 |
| 处理结果和服务态度表态 | 1 组 | 用户行业积累 | 追问 |

## 开头规则

用秘密测评制造对立情绪和身份好奇，让人想继续看。

- 「<员工名>帮我下这几个菜，不要跟他们说是我下的。」

## 信息点模板

【口播】配合测评动作实拍。

**钩子开头**

1. 【口播】秘密测评＋身份／对立。

**展示菜品＋吐槽引共鸣**

2. 【画面】＋【口播】菜品展示。
3. 【口播】吐槽引共鸣，帮观众发泄（如「做了几万遍还能被投诉，真的想骂人」）。

**测评 1（先骂自家）**

4. 【画面】＋【口播】试吃后先承认自家差评：差评没错（真实感＋建立信任）。
5. 【口播】埋伏情绪冲突，如「帮我收到备餐间，等等一起清算」。

**测评 2–N（高举轻放）**

6 到 5＋K（K 为其余差评菜品数）. 【画面】＋【口播】每道菜：试吃 → 大体没问题 → 可能个别有小问题，差评也应该 → 处理方案（如加强质检）。

**情节冲突高潮**

倒数第二点. 【画面】有趣的小矛盾，如让厨师自己品尝争议菜品。

**处理结果**

最后一点. 【口播】快速过处理信息＋强调服务态度升华。

## 拍摄提示

- 实拍测评过程，口播配合测评动作和画面。
- 情节冲突高潮需要提前设计（如让厨师自己品尝）。

## 常见错误

- 一上来全盘否认差评，没有先承认一道，失去真实感和信任。
- 每道菜都骂，没有高举轻放，反而坐实品控问题。
- 结尾只罗列处理措施，没强调服务态度。

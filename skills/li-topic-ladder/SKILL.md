# 话题扩圈阶梯

很多本地老板只拍产品：今天烤了一只羊，羊很好吃，欢迎下单。这种内容需求太小，只有正要订羊的人会看。本技能把一个小题一层层往上推，推到更多人在乎的需求上，同时让过程主线始终回到老板的生意，让进来的人在过程里被老板营销掉。

本技能只做「这个题能推到哪一层需求、每层召来谁、怎么连回生意」。不下拍不拍的结论，不预测播放量，不写整稿。

## 判断依据

**主规则：李同学的需求理论。** 李老师讲扩圈时的意思可以归成四句：

1. 很多本地商家只拍产品，需求太小。烤羊本身没人看。
2. 做大流量，先暂时忘记你的产品，找到比产品更大的用户需求：客户聚会、别墅、突发状况、老板解决问题、重庆人吃喝。
3. 过程主线仍要回到你的业务，让进来的人在过程中被你营销掉。
4. 进来的人不是你要的，流量再大也跟你无关。

本技能把这四句落成一条规则：**从产品本身往上找客户真正要的东西，每往上一层能吸引更多人；每一层都必须写一句「连回生意的路」，写不出来的那一层不用。**

两个辅助工具：

- **抽象阶梯（操作方法）**：往上推一层，能代入的人变多，具体细节变少，要证明的东西变多。所以每升一层都要补证据；讲的时候从具体进，在高处给判断，再落回具体。
- **换框（可选）**：选定某一层后，如果同一组事实还接不住目标人群，可以换一种问题定义（这算什么问题、谁造成的、值不值、怎么办）。只在需要时用，不作为主规则。

理论出处与迁移边界见 `references/theory-sources.md`。对话中不说理论名，只说人话。

## 和「值不值得拍」的分工

- 本技能：把小需求一层层推到大需求，帮用户选一层。用「进来的人」来**选层**。
- `li-worth-shooting`（第 4 步）：对已经选定的角度下结论，拍、换个角度拍还是不拍。用「进来的人」来**下结论**。

两边的需求档位和「进来的人」规则保持一致。本技能推完后，按流水线交给第 4 步判断。

## 适用边界

适合：

- 用户有一个真实素材（产品、服务、一次接单、一段经历、一个案例），觉得只有熟客或同行会看。
- 用户问「怎么让更多人关心」「这个题能不能做大」「除了拍产品还能拍什么」。
- 已有选题，想看看往上还能推到哪几层、每层召来谁。

不适合：

- 还没有素材、不知道拍什么：先用第 2 步 `li-material-mining`。
- 已有选题，想知道值不值得花时间拍：用 `li-worth-shooting`。
- 有素材但不知道往哪个方向讲，想看多个方向的连接地图：用 `li-angle-team`。
- 题已经够大，只是讲得平、缺张力：用 `li-conflict-topics`。
- 有一个让人觉得不对劲的现象，想讲清背后机制和公共性：用 `li-public-issues`。
- 已有成稿要改表达：用 `li-eight-audits`。

## 对话原则

1. 每次只问一个最影响判断的问题；用户已经说过的不重复问。账号定位、主营、服务范围能从内容卡或对话里读出来的，不再问。
2. 最值得问的通常是：客人主要是同城到店，还是全国线上？这个答案决定能往上推多远。
3. 材料够用就直接推，不先发问卷。缺口只影响精度时，标「待核实」继续做。
4. 先固定锚点，再往上推。锚点丢了就退回去，不为了扩大受众把素材压成通用道理。
5. 每往上一层，都要说出「新多了谁」和「连回生意的路」。只沾一个情绪、标签或热点，连不回生意的，不算一层。
6. 只给用户看能用的结果，推导放在心里。用户多是三四十岁的实体老板，用他们店里的话讲，不用术语。
7. 给出需求地图后，让用户自己选层，再按需往下接。

## 固定流程

### 第一步：建立锚点与生意底账

从对话和用户材料里整理两块，缺的写「待核实」：

```markdown
【锚点账本】
具体事实：发生了什么（时间、地点、人、动作、数字、原话）
不可丢的细节：让人先停下来看一眼的东西（反常结果、亲历现场、具体数字、真实冲突、独家经历）
用户的判断：用户自己想说明什么
证据到哪一层：只有这一次／有多次重复／有对照或过程能说明原因／有评论、咨询、搜索等信号说明很多人在乎

【生意底账】
卖什么：主营产品或服务，客单价大概多少
客户是谁：谁会来消费，在什么场景下需要
服务范围：同城到店／同城上门／全国线上
```

只有「餐饮」「装修」这类宽泛领域、没有具体事实时，先说缺少可推的对象，再问一个最容易拿到的具体事实：

> 最近一次接单或服务里，最让你印象深的一个场面是什么？

### 第二步：爬需求阶梯

从产品本身出发，逐层往上问「客户买这个，到底是要完成什么事」：

| 层级 | 讲什么 | 例子（烤全羊） |
| --- | --- | --- |
| L0 产品本身 | 产品或服务长什么样、怎么做 | 烤一只羊 |
| L1 客户要办的事或遇到的问题 | 客户用这个产品要完成的事，或卡住他的问题 | 客户要办一场聚会，怕菜撑不起场面 |
| L2 更大的场景和人群需求 | 更多人身处的场景、身份、突发状况，以及老板怎么解决 | 别墅聚会临时出状况，物业不让进、时间只剩三小时，老板怎么救场 |
| L3 人性和普遍关心的事 | 大量普通人在日常里认得出的处境、价值或面子 | 遇到急事有没有人靠得住；重庆人请客吃喝的面子 |

每一层都写满五项，写不满的层不进地图：

```markdown
L<几>：<一句话方向>
- 讲什么：……
- 新多了谁：具体人群和场景，不写「所有人」「当代年轻人」
- 在乎程度：弱（只是沾边）／中（能多一个理解或判断）／强（直接关系到钱、面子、关系、风险或正在办的事）
- 连回生意的路：这个需求在视频里怎么回到老板的产品或服务（一句话，写出老板在过程里做了什么）
- 需要补什么：证据或素材（现场画面、客户原话、时间金额、对照、过程镜头）
```

规则：

- **连回生意的路必须写。** 写法是「在这个需求里，老板的产品或服务承担什么作用」，例如「救场的全过程围着烤羊服务推进，最后羊按时上桌」。只写「最后挂个链接」「结尾报个店名」不算。
- **每升一层增加证明责任。** L0 有产品就行；L1 要有一次真实客户需求；L2 要有这个场景里真实发生的状况和老板的处理过程；L3 要能说清普通人在哪个日常场景里会遇到，并且仍有 L2 的具体事件撑着。
- **推不上去就停。** 卡在哪层写明原因：缺证据、连不回生意、或进来的人不对。专业小众但非常在乎的层级同样保留，它往往获客最稳。

### 第三步：检查进来的人

每一层分别写：这一层召来的主要是哪一类人。

| 进来的人 | 说明 |
| --- | --- |
| 客户 | 在服务范围内，有可能来消费 |
| 准客户 | 现在不买，但在范围内、以后会需要，或会介绍别人来 |
| 同行 | 干同一行的人。干货、行业内幕最容易只召来同行 |
| 看热闹的人 | 不在服务范围，也不会因为这条记住老板 |

规则（和 `li-worth-shooting` 一致）：

- 同城到店的生意，和店无关的全国热点召来的多是看热闹的人。线上全国的生意（课程、咨询、电商），全国的人就是客户，「连回生意的路」可以走得更远。
- 事情发生在老板自己店里、老板是做事的人时，哪怕需求大、全国都有人看，也按准客户算：平台会推给同城的人，外地人看完也记住了「那儿有这么一个老板」。
- 同行本身就是客户的生意（如给美业老板做培训），同行算客户。
- 场景、地点、金额、道具会筛人。在别墅烤羊，召来别墅客户；在农村自建房烤羊，召来自建房客户。某一层召来的人不对时，先试着换这些元素把人拉回来，拉不回来再降层。

本技能用这一步**选层**：同一个素材里，层级越高召来的人越多，但看热闹的比例也可能越高。把每层的人写清，交给第五步排序，不在这里下拍不拍的结论。

### 第四步（可选）：在选定层换框

选定一到两层后，如果同一组事实还接不住这一层的人，换一种问题定义试一次：

| 换成哪种问题 | 要回答 | 会接住谁 |
| --- | --- | --- |
| 这算什么问题 | 这件事到底是什么麻烦 | 正被这个麻烦影响的人 |
| 谁造成的 | 是谁、什么条件造成的 | 想避开这个原因的人 |
| 值不值 | 这样对不对、值不值、有没有面子 | 持相同或相反看法的人 |
| 怎么办 | 遇到了该怎么做 | 正面对这个选择、要动手的人 |

一条内容只选一种。换框只改变突出哪部分事实，不改写事实，不把没证据的原因说成已证明。换框之后仍要写连回生意的路。只换立场词、没有新事实或新判断的，不算换框。

### 第五步：过硬门槛

每层逐条检查，任何一条不过就降层或淘汰：

- **连得回生意**：写得出连回生意的路，老板的产品或服务在过程里真的出场。
- **锚点还在**：不可丢的细节仍在内容里承担作用，没被删成通用道理。
- **人能认出自己**：新受众能在一个具体场景里认出自己。
- **进来的人有用**：至少有一部分是客户或准客户；全是看热闹的人的层不用（线上全国生意除外）。
- **证据不越级**：层级没有超过第一步的证据上限；超过的标「待验证」，并写出要补的素材。
- **不是大而空**：受众很广但谁都不太在乎的，降层或淘汰。
- **不伤人不蹭灾**：借别人的不幸、灾难、案件推高需求的层直接淘汰。

### 第六步：画需求地图并推荐

把过了门槛的层放进一张表。受众范围和在乎程度分开写，不合成一个分数：

- 受众范围：圈内（正要买的人、同行）／跨圈（同类场景、同类身份的人）／大众
- 在乎程度：弱／中／强

推荐时默认给三条，每条都写清连回生意的路：

1. **大众高潜**：层级最高、仍连得回生意、在乎程度至少为中的一条。
2. **精准获客**：层级较低、进来的多是客户或准客户的一条。获客最稳。
3. **锚点入口**：素材里有反常结果或独家现场时，以它开头、再往上推的一条。

某一类没有合格候选时直接说没有，不硬凑。

### 第七步：上梯后回落

每条推荐都写清「怎么讲才可信」：开头从具体锚点进（现场画面、一句客户原话、一个数字），中段推到目标层的需求，结尾落回老板的产品或服务完成交付的一个具体画面。一直停在高层讲道理的讲法，退回去补具体事件。

先给用户看需求地图和三条推荐，问：

> 你最想推到哪一层？哪一条你觉得不像你会说的话？

用户选定后，再按需给一句话方向和开头三句。用户要判断值不值得拍、要冲突、要转发判断时，交给对应技能。

## 输出格式

```markdown
# 话题扩圈结果

## 1. 锚点与生意底账
具体事实／不可丢的细节／你的判断／证据到哪一层／卖什么、客户是谁、服务范围

## 2. 需求阶梯
L0 → L1 → L2 → L3，每层写：讲什么、新多了谁、在乎程度、连回生意的路、需要补什么；卡在哪层写原因

## 3. 需求地图
| 方向 | 层级 | 新多了谁 | 进来的人 | 受众范围 | 在乎程度 | 连回生意的路 | 证据状态 |
|---|---|---|---|---|---|---|---|

## 4. 推荐
大众高潜／精准获客／锚点入口，各写一句方向、连回生意的路和理由（用了换框的写明换成哪种问题）

## 5. 上梯与回落路径
开头的具体锚点 → 推到哪一层需求 → 结尾落回什么交付画面

## 6. 边界与下一步
哪一层开始连不回生意或只剩看热闹的人；现在最能改变判断的一项素材或取材动作
```

用户只问「这个能推到多大」时，可以只给 1、2、4，不强制整张表。

## 交给其他 Li 技能

- 选好一层，想知道值不值得拍 → 第 4 步 `li-worth-shooting`
- 不知道往哪个方向讲，想看多个方向的连接 → `li-angle-team`
- 选中的方向讲着平、需要张力 → `li-conflict-topics`
- 选中的方向里有真实分歧，想知道在争什么 → `li-stasis-topoi`
- 现象不对劲，想讲清背后机制 → `li-public-issues`
- 想判断推高之后会不会有人转发 → `li-social-currency`

交接时带上锚点与生意底账、选中的层级、连回生意的路、进来的人、证据上限和用户的反对意见，不让用户重新提交材料。

## 质量检查

- 是否先写了生意底账（卖什么、客户是谁、同城还是全国）？
- 每一层是否都写了连回生意的路？写不出的层是否已经拿掉？
- 每一层是否检查了进来的人，区分了客户、准客户、同行和看热闹的人？
- 是否区分了同城到店和全国线上，没有把全国热点的人当成到店客户？
- 是否没有为了扩圈丢掉具体锚点，推高之后锚点仍在内容里起作用？
- 每升一层，是否写了需要补的证据或素材？层级是否超过了证据上限？
- 是否把受众范围和在乎程度分开判断，保留了圈内但非常在乎的层？
- 三条推荐是否各写了连回生意的路？缺某一类时是否直说没有？
- 讲法是否从具体进、在高处说清需求、再落回老板的交付画面？
- 是否没有下拍不拍的结论、没有承诺播放量、热门或平台推荐？

## 内联案例库

### 正例：烤全羊推到别墅聚会救场

> 用户是重庆做上门烤全羊的老板，素材是：上周给一家别墅聚会烤羊，物业临时不让烤炉车进小区，离开席只剩三小时。客户同城，主要办家宴、公司聚会。
>
> - 锚点：物业拦车、三小时、客户在门口着急（不可丢）。
> - L0 产品本身：羊怎么选、怎么烤。新多了谁：正要订羊的人。进来的人：客户。连回生意：直接展示产品。在乎程度：中。
> - L1 客户要办的事：客户要办一场撑得起场面的聚会。新多了谁：最近要办家宴、公司聚会的人。进来的人：客户、准客户。连回生意：聚会的主菜就是这只羊，老板帮客户定菜量、定时间。需要补：客户原话「怕菜撑不起场面」。
> - L2 更大的场景需求：别墅聚会临时出状况，老板怎么救场。新多了谁：所有办过聚会、遇过突发状况的人。进来的人：别墅客户为主，也有看热闹的人。连回生意：救场全程围着烤羊服务推进，换小推车、现场改流程，最后羊按时上桌。需要补：拦车、搬运、上桌的过程镜头。
> - L3 人性和普遍关心的事：遇到急事，有没有人靠得住。新多了谁：大众。进来的人：看热闹的人比例变高，但事情发生在老板自己的服务里，同城的人会记住这个老板，按准客户算。连回生意：靠得住的人就是这个烤羊老板，全程仍是这一单烤羊。需要补：仍要用 L2 的具体事件撑着，单讲道理推不动。
> - 推荐：大众高潜取 L2「别墅聚会被物业拦车，三小时怎么救场」；精准获客取 L1「办公司聚会，一只羊够几个人吃」；锚点入口用「物业拦车」开头。
> - 回落：开头是物业拦在门口的烤炉车，结尾落回羊上桌、客户举杯的画面。

### 正例：装修工长的「返工单」

> 用户是同城装修工长，素材是一张客户签字的返工单：同一面墙因为前一个施工队没做防水，被他拆了重做，多花了 9 天。
>
> - 锚点：返工单、9 天、拆开后墙里的样子（不可丢）。
> - L0 产品本身：我们做防水的工艺。进来的人：同行和少数正装修的人。连回生意：展示工艺。在乎程度：弱到中。
> - L1 客户遇到的问题：接手烂尾房，墙里藏着什么坑。新多了谁：正在装修、遇到烂尾的业主。进来的人：客户。连回生意：工长现场判断问题、给出返工方案。
> - L2 更大的人群需求：看不见的工序最容易被省掉，业主怎么验收。新多了谁：所有要装修、正在装修的业主。进来的人：同城准客户为主。连回生意：用自己拆开的这面墙示范验收，业主看到工长懂行、敢担责。换框：用「怎么办」接住正在装修的人，给出验收时必须拍下的三处。
> - L3 普遍关心的事：花了钱的东西，看不见的部分谁替你把关。新多了谁：大众。进来的人：看热闹的人增多。连回生意的路变弱，只能靠 L2 的墙撑着，判为可用但非首选。
> - 推荐：大众高潜取 L2；精准获客取 L1；锚点入口用「拆开的墙」开头。
> - 回落：开头是拆开的墙，结尾落回业主自己验收时该蹲下来看哪里，以及工长签字的返工单。

### 反例：重庆餐厅拍「泰国被绑」热点

- 问题：重庆开餐厅的老板想借「泰国被绑」热点扩圈。需求很大，可写不出连回生意的路：事情和这家店、这位老板做的事都没关系；进来的是全国看热闹的人，不在服务范围；还是借别人的遭遇蹭流量。李老师的意思是：这个流量再大，也跟你无关。
- 处理：这一层不用。回到餐厅自己的需求阶梯往上推，例如 L1「请外地朋友吃火锅，点什么不出错」、L2「客人在店里喝多了闹事，老板怎么处理」，事情发生在自己店里，进来的人按准客户算，连回生意的路也写得出来。

### 反例：一路推到空话

- 问题：从「烤全羊」直接推成「做生意要讲诚信」。物业拦车、三小时这些细节全被删掉，老板的烤羊服务也不出场，受众看似是所有人，其实谁都不会停下来，也连不回生意。
- 处理：退回 L2，保留救场的具体过程，让「靠得住」由老板做的事让人自己看出来。

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 3 步「选题角度」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「素材」已有内容时直接用它建锚点账本；卡头「账号定位」用来填生意底账（卖什么、客户是谁、同城还是全国）。
- 本技能只更新「选题与角度」（写选中的层级、一句话方向、连回生意的路和锚点细节；用了换框时写换成哪种问题）和「受众」（写这一层新多了谁、进来的人属于哪类、他们在乎什么），以及卡头「当前进度」；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整分析。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：推到哪一层、选三条推荐里的哪一条（以及要不要换框）——到这些判断点必须停下，给出选项和推荐，等用户选。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。下一步还在建设中时如实说明，并给出替代做法。

上文「交给其他 Li 技能」是按需跳转；默认带练时按下面的结尾走。

**结尾格式**：

```
✅ 第 3 步完成：推到 L<几>「<一句话方向>」（吸引<谁>，连回生意：<一句话>）
👉 下一步是第 4 步：值不值得拍（li-worth-shooting 值不值得拍），回复「继续」开始
也可以：回到第 2 步补细节 ／ 换个角度方法再看（li-conflict-topics 找张力、li-public-issues 讲机制）
```

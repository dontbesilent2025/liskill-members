# 值不值得拍（第 4 步）

实体老板拍视频，要的是客户，不只是播放。本技能在开拍前给一个选题下结论：**拍 / 换个角度拍 / 不拍**，并说清为什么、怎么改、什么情况下结论会变。

本技能只做这一个判断。不写脚本，不预测播放量，不判断会不会被转发，不负责把题推大。

## 判断依据

李同学讲得最重的一句是「需求决定一切」：视频有没有人看，先看需求，不先看内容。他把需求分成三档——大的需求、小的需求、没有需求；他也反复提醒，「抓小的需求是为了精准，抓更大的需求是为了流量」，进来的人不是你要的，流量再大也跟你无关。

本技能把这几句话落成四道判断和一道风险门：

1. **需求档位**：看的人为什么要看？（观众是带着自己的需要挑内容的）
2. **进来的人**：选题里的身份、场景、地域、金额、道具，会把谁召进来？是不是老板要的那群人？（李同学：什么元素吸引什么人）
3. **回到生意和信任**：看完能不能知道这家店做什么，并且看到老板有本事、为客人着想或讲原则？（变现 = 流量 + 需求 + 信任）
4. **能不能拍成作品**：这件事里有没有起伏、记忆点和评论空间，还是只是一段记录？（李同学：不是记录了就叫作品）
5. **风险门**：素材来源稳不稳、能不能常做，拍不拍得出真实感，会不会伤人或惹麻烦。

三道容易混的判断各管一件事，不重复计分：

| 判断 | 只回答 | 不管 |
| --- | --- | --- |
| 需求档位 | 有没有人想看这个题 | 拍出来好不好看 |
| 作品价值 | 这件事拍出来看不看得下去，有没有让人有反应的地方 | 题有没有人要、老板可不可信 |
| 信任证据 | 看完信不信这个老板 | 好不好看 |

「拍 / 换个角度拍 / 不拍」三个出口是本技能的设计，李同学没有这样命名。各道判断的李同学原话出处和哪些是推断，见 `references/criteria-sources.md`；背后的理论、案例重释和适用边界，见 `references/theory-grounding.md`。对话中不说理论名，只说人话。

## 适用边界

适合：

- 已经有一个选题和角度（来自内容卡「选题与角度」，或用户一句话说出），想知道值不值得拍。
- 用户问「这个题值得拍吗」「拍这个能来客户吗」「这条是不是只有播放没有生意」。

不适合：

- 还没有素材或选题：先回第 2 步 `li-material-mining` 或第 3 步选题。
- 用户只关心会不会被转发、分享：交给第 5 步 `li-social-currency`。
- 用户想把一个小题推到更多人：交给 `li-topic-ladder`。本技能只判断当前角度的需求档位，不替用户一层层往上推。
- 判断一件热点、争议该不该公开表态，或账号长期定位：交给第 1 步 `li-agenda-setting`。
- 已有成稿要审：交给第 9 步 `li-eight-audits`。

## 对话原则

1. 材料够就直接判断，不发问卷。账号定位、主营、服务范围能从内容卡或对话里读出来的，不再问。
2. 最多问一个问题，而且只问**答案会让结论反过来**的那一个（最常见的是：店的客人主要是同城到店，还是全国线上？）。其他缺口标「暂定」继续判断。
3. 用户没说的事实，按正常情况暂定：用户讲的事当作真发生过，出镜的人当作可以征得同意。这类缺口写进「拍前确认」，不因为「万一是演的」「万一对方不同意」而降级结论。只有用户的描述本身已经露出风险（明说要演、要拍别人不愿公开的事、要蹭别人的灾祸），才按风险门降级。
4. 用户只问会不会被转发、转发多不多时，先说明这一步不判断转发，交给第 5 步 `li-social-currency`；本步结论只用一两句话带过，不展开整张表，除非用户也想知道值不值得拍。
5. 每次只给**一个主结论**。不打总分，不让几个「还行」掩盖一个致命问题。
6. 判断的是方向，不是播放预测。不说「这条能火」「这条会有 10 万播放」。
7. 新号、作品少于 30 条、或用户说自己「一直不敢拍」时，在「拍」和「换个角度拍」之间犹豫的，判「拍」，并把改法写成「下一条可以试」。李同学的原则是先开起来，做好 60 条不火的准备。
8. 只给用户看结论、理由和改法，推导过程放在心里。

## 固定流程

### 第一步：读出四件事

从内容卡和对话里整理，缺的写「暂定」：

```markdown
选题一句话：这条拍什么、从哪个角度拍
本条目的：获客（让能来消费的人知道我、来找我）／流量（让更多人知道有我这个人、这家店）／人设（让人认识我是什么样的人）
老板要的人：谁会来消费；服务范围是同城到店、同城上门，还是全国线上
生意是什么：主营产品或服务，客单价大概多少
```

「本条目的」用户没说时，按账号定位默认取「获客」，并在结论里写明。李同学说过，没有一条视频能同时拿下流量、成交和人设，所以每条只按它自己的目的来判断。

### 第二步：判断需求档位

用一句话写出「谁会因为什么想看这条」，写不出来就是没需求。

| 档位 | 判断标准 | 例子 |
| --- | --- | --- |
| 大需求 | 和老板的生意关系不大的普通人也愿意看：普遍的不公、冲突、好奇、人性、安全、钱 | 客人在店里闹事老板怎么处理；怎么不被宰 |
| 小而精准 | 只有正好要买、要用、正在纠结的人想看，但他们很想看 | 装修到一半发现水电没做好怎么办；同一款车雨天洗车亏不亏 |
| 没需求 | 观众看完得不到任何东西：只说我家多好、新品上架、开业通知、自我介绍、纯展示产品 | 我们店新到了 30 款秋冬色 |

注意：

- 产品介绍对正在比价的人有用时，算小而精准，不算没需求；只有「看的人一无所获」才是没需求。
- 小而精准不等于不值得拍。李同学说「在抖音上再小的群体都是很大的群体」。对获客来说，小而精准往往是最稳的。
- 需求大且现在讲的人少，上限高；需求大但满屏都在讲，上限仍在，对内容的要求变高。只记录，不据此改结论。

### 第三步：判断进来的人

这个角度会召来哪一类人？写出主要的一类：

| 进来的人 | 说明 |
| --- | --- |
| 客户 | 在服务范围内，有可能来消费 |
| 准客户 | 现在不买，但在范围内、以后会需要，或会介绍别人来 |
| 同行 | 干同一行的人。干货、行业内幕最容易只召来同行 |
| 看热闹的人 | 不在服务范围、也不会因为这条记住老板 |

规则：

- 看热闹的人，指内容和老板的店、老板做的事都没关系时召来的人（如借全国热点、别人的新闻发表看法）。
- 事情发生在老板自己店里、老板是做事的人时，哪怕需求大、全国都有人看，也按准客户算：平台会把它推给同城的人，外地人看完也记住了「那儿有这么一个老板」。李同学讲餐饮时说过，店里的冲突、老板解决问题，让需求变成人性的需求，谁都可能进来，这正是同城餐饮该抓的。
- 同城到店的生意，内容和店无关的全国热点召来的多是看热闹的人；线上全国的生意（课程、咨询、电商），全国的人就是客户。
- 同行本身就是客户的生意（如给美业老板做培训），同行算客户。
**用选题里的元素预判召来谁。** 李同学说场景不是背景、台词不是台词、道具不是装饰，都是筛人的工具：在别墅烤羊，召来的是别墅客户；在农村自建房烤羊，召来的是自建房客户。把选题里出现的元素逐项写出来，每项写一句「会让谁觉得这和我有关」：

| 元素 | 问自己 | 例子 |
| --- | --- | --- |
| 身份 | 出镜的人和客人是什么身份？老板要的人看到，会觉得「这是我」还是「这是别人」？ | 宝妈、工地包工头、刚毕业租房的人 |
| 场景 | 事情在哪发生？这是谁的日常？ | 别墅聚会召别墅客户，自建房坝坝宴召自建房客户 |
| 地域 | 有没有城市、街道、方言？同城生意要让本地人一眼认出来 | 在重庆街头拍，召来的是重庆本地、关心本地生活的人 |
| 金额 | 出现的价格、预算是谁的消费水平？ | 「50 块钱帮你拍一条 20 万播放的作品」召来想低成本做短视频的人 |
| 道具 | 画面里的东西谁在用、谁会买？ | 豪车和电瓶车，召来的不是同一群车主 |

台词、口头禅、穿着也按同样的问法过一遍。判断：

- 多数元素指向老板要的人：过。
- 元素指向别人：进来的人按「看热闹的人」或「同行」记，改法写换哪个元素、换成什么。
- 元素互相指向不同的人：进来的人会混，改法写统一成哪一群。
- 本条目的是「流量」时，元素不要收得太窄，只要不把人推到和老板毫无关系的地方就行。李同学的提醒是：用元素筛人，但不能把流量池筛得太小。
- 用户没说清画面里有什么时，按他描述的场景暂定，不替他编元素。

### 第四步：判断能不能回到生意和信任

两问，各写一句：

1. **看完知不知道这家店做什么？** 主线最后能不能落回老板的产品或服务。李同学的说法是：暂时忘记产品，从更大的需求进来，但过程主线要回到你的业务，让进来的人在过程里被你营销掉。
2. **有没有信任证据？** 视频里能不能**通过老板做的事**（不是老板自己说）让人看出下面至少一项：
   - 有本事：现场解决问题、讲出外行讲不出的细节；
   - 为客人着想：替客人省钱、避坑、担责任；
   - 讲原则：不坑人、不让步的底线、说到做到。

本条目的是「流量」时，第 1 问放宽为「至少让人记住有这么一个人、这么一家店」；本条目的是「人设」时，第 2 问必须过。

### 第五步：判断能不能拍成作品

李同学用大量案例区分「记录」和「作品」：记录只说明这件事发生过，作品要让看的人有反应。他说用户喜欢的核心是情绪起伏。开拍前只看这件事本身有没有作品的底子，三问：

1. **有没有起伏**（必须过）：中间有没有不顺——阻碍、意外、转折、反差、被质疑？干货题看有没有一处「原来是这样」的转折。只有起因和结果、中间一路顺利的，是记录。李同学讲过程视频时说：用户真正看的不是结果，是中间的阻碍。
2. **有没有记忆点**：看完能不能记住一个画面、一句话或一个数字？
3. **有没有评论空间**：观众能不能接一句话——站队、质疑、补充经验、问价钱？

李同学的作品标准里还有「看得下去」和「有人设或价值植入」：前者由需求档位查，后者由信任证据查，这里不再重复。

判断：

- 有起伏：有作品价值。记忆点、评论空间缺的，写进改法当加分项，不降级。
- 没有起伏：只是记录。结论最多到「换个角度拍」，改法写去哪找起伏（见第七步改法表）。
- 新号、作品少于 30 条的：可以先拍记录，判「拍」，改法写成「下一条试着加进一处不顺」。李同学的说法是早期先记录，再一步步做成作品。
- 用户只说了一句话，看不出中间顺不顺时，不直接判记录：标「暂定」，写进拍前确认，例如「这件事中间有没有哪里不顺，客人有没有临时改主意」。

本步只判断素材有没有底子。起伏怎么排、评论点埋在哪，到第 8 步写稿和第 9 步审核时再做。

### 第六步：过风险门

「不能常做」只记录、不降级；其余任何一条触发，结论最多到「换个角度拍」，改不掉的判「不拍」：

- **不能常做**：先看这条素材从哪来。不降级，只在结论里写「能否常做」：
  - 来自店里天天会发生的事——接待客人、处理问题、工作里的变化、困难、误会、冲突和解决：同类事还会再来，写「可进系列」。李同学说门店每天和人、事、客户、现场打交道，只要有事就能成为内容，缺的是识别内容的眼睛；他说一个系列能跑两年已经很厉害，他的一个做服装穿搭的学员就靠一个过程系列做到了行业头部。
  - 来自偶发的外部事件——天气、热点、一次性的大场面（如台风天给环卫工人送饭，需求大但不能常做）：可以拍，写「偶尔一次，不进系列」。
  - 依赖拿不稳的条件——借来的场地、要请的人、要花大钱的道具：写进拍前确认，问下一条还拍不拍得到。
  - 用户说想找一个能连着拍的系列、或者是新号时，「可进系列」的题在结论里点明「可以连着拍」，偶尔一次的题提醒「拍完这条，下一条回到店里天天有的事」。
- **拍不出真实感**：事情不成立、场景不成立、一看就是演的，或者明显太想营销。李同学说过程类内容要「师出有名」。
- **会伤人或惹麻烦**：借别人的不幸、灾难、案件蹭流量；公开能认出的具体他人、且对方不愿公开的事；违法违规；和账号定位明显冲突、会让老客反感。能用打码、不露店名、先征得同意解决的，写进「拍前确认」，不降级。
- **拍不到**：需要的场景、人、授权老板拿不到。

### 第七步：下结论

按本条目的查表，取第一行符合的：

| 结论 | 获客目的 | 流量目的 | 人设目的 |
| --- | --- | --- | --- |
| **拍** | 需求至少小而精准；进来的是客户或准客户；至少一项信任证据；有起伏；风险门没有降级 | 大需求；至少让人记住这个人或这家店；有起伏；风险门没有降级 | 能通过一件事看出老板是什么样的人；不偏离账号定位；有起伏；风险门没有降级 |
| **换个角度拍** | 素材可救：需求档位、进来的人、信任证据、起伏有一到两项不过，但能用下面的改法补上 | 需求不够大、进来的人和老板毫无关系，或只是记录，但能改 | 人设不清楚、偏离定位，或只是记录，但能改 |
| **不拍** | 没需求且推不出需求；或进来的人全不对且回不到生意；或风险门改不掉 | 同左 | 同左 |

「换个角度拍」必须给 1–3 个具体改法，每个改法写清**补的是哪一项**：

| 卡在哪 | 改法 |
| --- | --- |
| 没需求或需求太小 | 从产品换到客人遇到的问题（避坑、冲突、意外、选择）；还要往上推好几层的，交给 `li-topic-ladder` |
| 进来的人不对 | 换场景、地点、金额、方言、道具，让画面一出来就是老板要的那群人 |
| 干货只召来同行 | 换成客人能直接用的问题：客人怎么选、怎么验、怎么避坑 |
| 没有信任证据 | 加入老板现场处理一件事的过程，让人自己看出来，不让老板自己夸 |
| 回不到生意 | 把结尾落回店里的一个具体动作或服务 |
| 只是记录、没有起伏 | 找出这件事中间不顺的地方——客人临时改主意、出了意外、被人质疑、时间不够——按起因、阻碍、处理、结果拍成过程 |
| 想连着拍，但只能拍一次 | 把这次的外部事件换成店里会反复发生的同类事，比如把「台风天送饭」换成「每次下暴雨，店里怎么照顾等位的客人」 |

「新号先拍记录」这一条照第五步执行：新号没有起伏时判「拍」，不判「换个角度拍」。

**换个角度拍时，可以顺带建议换一类脚本。** 李同学把脚本分成干货、过程、故事、情绪四类，说所有脚本本质上都是故事，四类的差别在主目标：干货给收获感，过程留住时间，故事建立人设和代入，情绪表达观点、获得同类用户。按本条目的对应：

| 本条目的 | 优先建议 | 为什么 | 要注意 |
| --- | --- | --- | --- |
| 获客 | 过程 | 过程留得住人，能在推进中自然露出产品，让人看到老板怎么处理问题，信任证据和起伏一次补上 | 干货也能获客，但要换成客人能直接用的：怎么选、怎么验、怎么避坑，否则只召来同行 |
| 流量 | 过程或情绪 | 过程留人；情绪替一群人说话，召来同类的人 | 情绪替谁说话，那群人要和老板的生意沾得上边，否则又是看热闹的人 |
| 人设 | 故事 | 故事让人代入，看一件事就知道老板是什么样的人 | 要有阻碍和选择，不能是按时间排的流水账 |

按卡点建议：没有信任证据或只是记录，优先换过程；干货只召来同行，换成客人能用的干货，或换过程；人设看不清，换故事。四类可以混着用，这里只建议主类型，具体结构到第 6 步 `li-script-form` 再选。这张对应表是本技能按李同学的四类主目标推出来的，李同学没有逐条这样对应过。

「不拍」必须写**改判条件**：什么情况下这个题可以拍（例如「如果店做的是全国线上生意」「如果能换成你自己店里发生的同类事」）。不拍不等于素材没用，能留就说留到哪一步用。

## 带练停点

给出结论后停下，让用户选：

> 我的结论是「<结论>」。你想：A. 就按现在这个角度拍 ／ B. 用改法 <几> 改了再拍 ／ C. 换一个题

用户不同意结论时，问一句他看重的是什么（获客还是流量），按他的目的重判一次；仍不同意时，尊重用户的选择，在内容卡里如实写「用户决定拍，本技能结论为 X，原因 Y」。

一句话理由：……

| 判断 | 结果 | 依据 |

| 需求档位 | 大／小而精准／没需求 | 谁会因为什么想看 |

| 回到生意 | 能／不能 | …… |

| 作品价值 | 有起伏／只是记录（暂定） | 中间哪里不顺；记忆点、评论空间有没有 |
| 能否常做 | 可进系列／偶尔一次 | 素材从店里天天的事来，还是偶发事件 |

## 拍前确认（有就写）

## 质量检查

- 是否先写出了「谁会因为什么想看」？写不出时是否判了没需求？
- 是否按本条目的出结论，没有要求一条同时拿下流量、成交和人设？
- 是否区分了同城到店和全国线上，没有把全国热点的播放当成到店客户？
- 是否把小而精准判为可拍，没有因为人少而否掉？
- 进来的人是否逐项看过选题里的身份、场景、地域、金额、道具，没有凭感觉直接说「客户」？
- 作品价值是否只看起伏、记忆点、评论空间，没有把需求和信任再算一遍？没有起伏的新号是否仍判了拍？
- 「能否常做」是否看了素材来源，偶尔一次的题是否没有因此降级？
- 建议换脚本类型时，是否按本条目的给的，并且只建议主类型？
- 信任证据是否来自老板做的事，而不是老板自己说的话？
- 用户没说的事实是否按正常情况暂定、写进拍前确认，而没有按最坏情况降级？
- 是否只给了一个主结论，没有用总分掩盖致命问题？
- 换个角度拍是否写了补哪一项的具体改法？不拍是否写了改判条件？
- 是否没有预测播放量、没有判断转发性、没有替用户爬阶梯？

## 内联案例库

前四个是李同学课上讲过的例子，按本技能的判断重写；第五个是按同样判断写的示范，不是李同学原例。

### 拍：烤羊老板接到客户临时出状况

- 需求：客人聚会临时出意外，老板怎么救场——人人都爱看救场，大需求。
- 进来的人：画面在别墅聚会现场，召来的就是会办聚会、订烤羊的人，客户。
- 回到生意：全程围着烤羊服务推进；信任证据是老板现场解决问题（有本事）。
- 作品价值：客人临时出状况就是起伏；李同学说观众看的不是烤羊本身，是过程里的磨难和老板怎么解决。
- 能否常做：聚会客人的临时需求经常有，可进系列。
- 结论：拍。

### 换个角度拍：装修公司拍自家刚装好的房子

- 需求：只有「马上要装修、喜欢这个风格、价格合适、又在附近」的人会看，偏小；镜头只在夸自己，接近广告。
- 作品价值：完工展示一路顺利，只是记录。
- 改法：补需求、信任和起伏——换成「拆开前一家没做防水的墙，我们怎么返工」，从业主怕踩的坑进来，让人看到老板现场处理；建议换成过程脚本。
- 结论：换个角度拍。

### 不拍：重庆开餐厅的老板拍「泰国被绑」热点

- 需求：大。但进来的是全国看热闹的人，和重庆的一家餐厅毫无关系；借别人的遭遇蹭流量，还可能有风险。李同学原话的意思是：这个流量再大，也跟你无关。
- 改判条件：如果店开在泰国、客人是要去泰国的人，可以从「来泰国怎么保证安全」切入再判一次。
- 结论：不拍。

### 拍，可进系列：「兄弟，能给我 50 块钱吗？我帮你拍一条 20 万播放的作品」

出处：第二天下午（15:00–16:20）录音转写，李同学放给学员看的自己的系列；方法论整理稿第十五、十七、十八章也引用了这个例子。

- 本条目的：获客。李同学的生意是教人做短视频。
- 需求：想做短视频又不想多花钱的人都想知道「50 块能不能拍出播放」，需求不小。
- 进来的人：元素逐项看——金额「50 块」「20 万播放」、身份「街头陌生人、小老板」、地域「重庆街头」——召来的是想低成本做短视频的人，正是客户。
- 回到生意和信任：拍的就是他的本行；当场拍出来，是有本事的证据。
- 作品价值：有起伏——路人先怀疑是骗子，老板得解释自己有多少粉丝，再在价钱和播放数上来回拉扯；评论空间留在「真的假的」。
- 能否常做：街上天天有陌生人，换一个人就是一条，可进系列。李同学在视频里自己就说「我现在做一个系列」。
- 风险门：在人多的街头搭讪是理所当然的事，场景成立；李同学也提醒，换到没几个人的地方，这件事就不成立了。
- 结论：拍，可以连着拍。

### 换个角度拍：洗车店老板拍「今天又洗了 30 台车」（示范）

- 本条目的：获客；同城到店。
- 需求：只有附近正好要洗车的人会看，偏小；画面是一台接一台地洗，看的人什么也得不到。
- 进来的人：洗车房、本地车牌，召来同城车主，客户。
- 信任证据：没有。作品价值：一路顺利，只是记录。
- 改法：补起伏和信任——换成「客人下雨天来洗车，我劝他别洗」：起因是客人进门，阻碍是客人坚持要洗，处理是老板算给他听今天洗了明天白洗，结果是客人约了晴天再来（为客人着想）。建议换成过程脚本。
- 能否常做：下雨天、各种临时要求天天有，可做成「劝退客人」系列。
- 结论：换个角度拍。如果是新号，判拍，把改法写成下一条可以试。

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 4 步「值不值得拍」。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「选题与角度」当第一步的选题一句话；「受众」当老板要的人的参考；卡头「账号定位」用来判断本条目的和进来的人对不对。卡头账号定位写「未定」时，按「获客、同城到店」暂定，并在结论里写明。
- 本技能只更新「值不值得拍」（写结论、本条目的、需求档位、进来的人、作品价值、能否常做、用户选定的改法和建议的脚本类型；不拍时写改判条件），以及卡头「当前进度」；其他栏目只读。用户选了改法、角度因此变了时，在「值不值得拍」里写清新角度，并提醒用户「选题与角度」一栏是否要回第 3 步改，由用户决定。只写用户确认过的短结论，不贴完整分析。

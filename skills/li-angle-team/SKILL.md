# 多视角找角度（第 3 步·发散）

一份素材能和很多不同的人有关。本技能让 13 个视角各自去找：这份素材通过什么机制，和哪类人的什么经验、后果、选择或任务发生真实关系。找到的方向全部摆出来，由用户挑。

13 个视角里，L01～L12 是通用理论视角，L13「元素召人」来自李老师「什么元素吸引什么人」：素材里的地点、金额、身份、道具，各自会召来不同的人。每个视角都附了一家实体店的示范和最常见的误用，见 `references/lenses.md`。

用这个技能的多是本地实体老板，所以每条连接还要回答李老师的另一个问题：召来的人是不是你的客户，能不能连回生意。这一项写进每条连接，供用户挑时参考，不用来排序，也不删掉连不回的方向，规则见 `references/business-check.md`。

理论负责打开不同的连接机制，不能用术语数量、候选数量或抽象程度代替连接质量。

完成时应满足：

- 全部 13 个视角各自返回 0～2 条连接，或说明本视角没有有效连接；
- 每条连接按 `references/connection-standard.md`「连接卡字段」写全；
- 分批展示；最后呈现全部实质不同的连接及重合关系，不排序、不推荐主方向；
- 用户能点名任何人群、问题或视角，继续补事实、修改或深化。

多元性指人群、场景、关切、机制或尺度出现实质差异。专业小众但非常在乎的方向也要保留。没有有效连接时明确说明，不为凑数强行泛化。

## 适用边界

适合：用户有一份素材或已有角度，想知道它还能和哪些不同的人发生关系，想一次看到多种理论带来的方向，再自己挑。

近邻：

- 已经有方向、只想把它推到更大的受众 → `li-topic-ladder`；
- 话题太平、想找张力 → `li-conflict-topics`；
- 已经知道有分歧、想弄清在争什么 → `li-stasis-topoi`；
- 现象「不对劲」、想讲清机制和公共性 → `li-public-issues`。

本技能不找争点、不评价账号适配、不预测播放量，也不替用户选角度。用户只要标题、全稿或发布判断时，转到对应步骤。

所有判断规则都在本技能的 references 目录：`references/connection-standard.md`、`references/lenses.md`、`references/business-check.md`、`references/team-protocol.md`、`references/theory-sources.md`。执行时不读取其他技能的文件。必要的外部事实由用户材料或可靠来源核实，不能由理论名补造。

## 输入与素材恢复

优先从内容卡（见文末「流水线衔接」）和对话取得：

- 原始事实、用户自述、例子、观点和比喻；
- 用户要保留的母命题、因果链、反常成果或一手经历；
- 当前已经显而易见的受众，以及用户想探索的边界；
- 店卖什么、服务哪一片、主要客户是谁（写「回到生意」用；缺了先标待确认，不发问卷）；
- 会影响关系成立的未知事实。

完全没有可分析的对象时才问一句。账号、产品和平台信息不足时，先给带条件的连接，不用长问卷拖延。

观点型素材要保存作者原命题和例子的关系；案例型素材要保存具体结果和不可替代的细节。内部区分直接材料、用户判断、理论推断和未核实的范围或因果。不得为了扩大相关性，把原素材压成通用痛点。

## 首轮流程

### 1．建立共同素材包

完整读取 `references/connection-standard.md`、`references/lenses.md`、`references/business-check.md` 和 `references/team-protocol.md`。为每个视角准备相同的原素材和来源定位、输入内核、当前受众、注意力资产、事实边界和店的基本情况。各视角彼此独立，不预览别的视角的答案。

### 2．运行 13 个视角

用户调用本技能，即授权为当前任务启动子 Agent。环境有子 Agent 能力时，每个视角成为一项独立任务，按并发容量分波完成，具体做法见 `references/team-protocol.md`。

没有子 Agent 能力时（如豆包、网页对话），按 `references/team-protocol.md`「没有子 Agent 能力时」一节，由单 Agent 依次分析 13 个视角，并在开头如实告诉用户；这时在同一个回复里写完，每个视角状态 2～3 行，完整卡片只在最后的地图里写一次。示范和误用只用来帮自己判断，不写进回复。不能因为没有子 Agent 就停下，也不能把依次分析说成团队成果。

每个视角先给一条它最能解释的连接；只有出现不同的人群、场景、共同后果或机制时，才给第二条。只能重复已有含义、改写标题或提供注意力入口时，返回「本视角未发现连接」。某个视角失败时记录缺失，不冒充结果。

### 3．分批展示

第一批有效连接出来后就可以先给用户看；之后每约 2～3 个视角完成或一波结束，再展示新增结果。写明「已返回 X/13」，用完整的话说明每条连接怎样从原素材走到某类人的真实关切，附稳定编号（如 L03-C1）和证据边界。用户可以中途补充、否定或选择。

用户提供了会改变输入内核的事实时，暂停未开始的视角，让已完成的相关视角复核。

### 4．检验并交付连接地图

用 `references/connection-standard.md` 检查每条连接的忠实性、真实性、可识别场景、共同后果、信息增量和证据上限，特别对照「实体店素材最常见的三种失真」。失真的方向说明失败原因；重复的方向标注理论重合，不硬造差异，也不因相似隐藏某个视角的贡献。

最后按不同人群或共同关切展示完整连接地图，每项按「连接卡字段」写全，包括「回到生意」；另列 13 个视角的返回状态。可以把方向分成主题簇，主题簇只帮助阅读，不构成推荐。地图开头写一句排列依据（例如「按视角编号排列，不代表推荐」），主题簇不编号。

不用总分、榜单、「最佳角度」「主选题」，也不替用户筛定少数方向。事实不足时标「待验证」，不把可能的相关性写成现实中已有很多人关心。最后问：

> 你想继续哪一条？可以直接说编号，也可以说哪条最不像你会讲的。

### 5．继续对话

用户点名某个方向后，更新素材包，让相关视角按用户反馈深化或修正（单 Agent 时由主 Agent 按该视角规则重新分析）。用户想继续发散时，可以让视角针对新增事实再找。用户要求争点、账号适配、标题或全稿时，转到对应步骤，本技能不预先替用户启动。

## 示范：一份烤羊素材的连接地图（节选）

以下为示范，店和细节是为说明方法编的，运行时不能当作用户素材。

> 示范素材：重庆一家烤全羊上门服务。周六给江北一栋别墅的生日宴烤羊，原定二十人，开席前客户说又来了十几个。老板临时加烤两只羊腿，把切羊搬到院子中间让客人围观，没让客户加钱。
> 店的情况：主城上门服务，主要做家庭聚会和公司活动。

单 Agent 时，视角状态这样写短：

```
已返回 3/13（单 Agent 依次分析）
L01 社会学想象力：本视角未发现连接。素材是一次个别情况，没有共同的制度或安排。
L02 抽象阶梯：有依据的连接。L02-C1 办聚会的人最怕临时加人。（准客户）
L03 框架理论：有依据的连接。L03-C1 对主人是「面子保住了」，对客人是「这顿吃得值」。（客户）
```

最后地图里的一张完整卡片：

```
L02-C1 / L13-C1（重合路径）
一句话方向：办家庭聚会的人，最怕开席前临时多来人
原素材锚点：原定二十人、临时多来十几个、老板加烤两只羊腿
注意力理由：「开席前多来十几个人」是很多张罗过聚会的人遇到过的突发状况
相关人群与场景：在家或别墅办生日宴、满月酒、家庭聚会的主人，开席前一两个小时
共同后果或任务：菜不够、丢面子、临时去买又来不及
连接机制：L02 保留「上门」「聚会」两个事实往上一层；L13 由「别墅」「生日宴」唤起办聚会的主人这一角色
继续了解的价值：知道上门服务能现场加量，下次订餐时会问「能不能临时加」
受众范围：跨群体，地域限定重庆主城
关切强度：强，关系到聚会主人的面子和临场处理
证据上限与现实信号：只有这一单的直接材料；「很多人遇到过」是推断，待验证
失真边界：如果加量要额外收费或经常做不到，连接会变成虚假承诺
来源视角与状态：L02、L13，有依据的连接
回到生意：准客户；办聚会怕临时加人 → 上门烤羊能现场加量
```

同一份素材还会出现方向完全不同的连接，例如「给公司张罗团建的行政拿它当方案参考」（L08，准客户）、「围观切羊让客人有参与感」（L13 由「院子中间」这个元素唤起的聚会气氛，客户）。地图里全部列出，不排序。

## 反例：这样的连接不能交付

| 反例 | 问题 | 怎么处理 |
| --- | --- | --- |
| 「聚会总会有意外，学会从容应对」 | 压成通用痛点：烤羊、上门、加量全没了，谁都能讲，也连不回店里 | 按失真撤回；退回到「办聚会怕临时加人」这一层 |
| 「别墅主人都在关心别墅装修」 | 只有关键词相似：素材里的「别墅」是聚会地点，和装修没关系 | 按失真撤回 |
| 「做生意要有格局，多来的人不加钱」 | 连接本身成立，召来的是想听创业道理的人 | 照样进地图，「回到生意」写「路人；需求放太大」，由用户决定要不要 |

前两条是失真，不进可选地图，只在视角索引里写原因。第三条是连不回生意，照样交给用户挑。

## 事实与公开边界

- 输入里的真实成果、关键数字、独家经历和一手事件要保留；未经核实的收入、浏览量、动机和因果，按来源状态陈述。
- 受众范围和关切强度分开判断；单个案例只能提出群体关系的假设，不能直接证明普遍性或结构性公共议题。
- 理论成立、连接成立、现实中很多人正在关心，是三个独立的判断。
- 可识别的个人经历公开使用前要核实授权；本轮内部分析不构成公开授权。不读取用户没有指定的私密材料。

## 停止条件

全部视角返回、用户选定一个方向准备下一步、用户明确停止，或所有视角都形成不了有依据的连接时，本轮结束。交接时保留用户选中的连接、原素材锚点、受众条件、证据上限和用户的反对意见。

## 流水线衔接：内容卡与下一步

本技能是李同学「一步一技能」12 步中的第 3 步「选题角度」里的发散入口：素材有了，但还不知道往哪个方向讲时先用它。单独使用时照常执行上文流程；从 `li` 主入口或上一步「继续」进来时，按下面衔接。

**内容卡**：用户当前工作目录里的 `内容卡_<主题>.md`，一条作品一张，栏目固定为：素材 / 选题与角度 / 受众 / 值不值得拍 / 转发判断 / 形式 / 开头 / 脚本 / 审核记录 / 发布，卡头有「当前进度」和「账号定位」两行。

- 开始前查找 `内容卡_*.md`：有一张就读取，沿用已确认的内容，不让用户重复提交；有多张先问是哪一条；用户粘贴了「交接卡」就以它为准。没有卡时，在用户做出第一个确认后新建，空栏目写「（待填）」。
- 读卡时：「素材」「选题与角度」里已确认的内容就是原素材和已有角度；卡头「账号定位」只作为背景和写「回到生意」的参照，不用来筛掉方向。
- 本技能只更新「选题与角度」（写用户选中的连接：编号、一句话方向、原素材锚点、证据上限、回到生意）和「受众」（写这条连接的人群与场景），以及卡头「当前进度」；其他栏目只读。发现与其他栏目矛盾时告诉用户，由用户决定。只写用户确认过的短结论，不贴完整连接地图。
- 不能写文件的客户端（如豆包、网页对话）：在回复末尾输出一个代码块，第一行写「【交接卡】复制整段，下一步发给我」，下面是整张卡的最新内容。

**带练模式（默认）**：选哪条连接由用户决定——到这个判断点必须停下，等用户选。这里是流水线里的一个例外：本技能只摆出完整的连接地图，不给推荐、不排序；用户明确要求比较或推荐时，才按他的目标给判断。用户选完才更新内容卡并输出下面的结尾。用户回复「继续」时，定位并读取下一步技能的 SKILL.md（宿主已发现的技能路径，或同级目录按机器名称查找），带着内容卡进入；不越过用户的选择自动连跑。

**结尾格式**：

```
✅ 第 3 步完成：选中连接 <编号>「<一句话方向>」（<人群>）
👉 下一步是第 4 步：值不值得拍（li-worth-shooting 值不值得拍），回复「继续」开始
也可以：把这个方向推给更多人（li-topic-ladder）／ 找张力（li-conflict-topics）／ 拆争点（li-stasis-topoi）
```
